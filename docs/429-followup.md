# 429 后续修复（2026-09-07）

用户在 d9ba87d 后反馈：监控中 43 条请求均失败，多条 gemini-3.7-flash-high / gemini-3.1-pro-low 最终返回 429，耗时约 52 秒；另一条 gemini-3.6-flash-medium 返回 `Penalty is not ena…` 的 400。

这是最终逻辑请求失败，不能解释为“仅记录了中间重试”。截图没有包含完整上游错误，本次尚未确认全部线上 429 的根因。当前可访问的本地容器数据库只有一个账号且请求日志为空，与截图中的部署数据不一致。

## 已确认并修复的缺口

1. **模型档位。** 补 demo 的 3.6→3.7 别名、3.7-high 按输入档位解析、3.5 固定档映射。模型选择完成后按实际模型校准 thinking/max output。例如 3.6-medium 现在转换为 3.7-medium，预算 4000，而不再原样发送 3.6 或带上默认 32768。
2. **错误详情丢失。** HTTP 200 SSE 的 error / response.error 原先仅留下 message，丢掉 details 中的 RetryInfo、错误原因、配额重置时间。现在保留原始错误并交给重试策略；流中途出错同样使用详情标记冷却。
3. **重试提示。** 支持自然语言 `try again in 1.5 seconds`、`quota will reset after ...` 及更多结构化键；短时同号重试窗口扩至 5 秒。结构化提示增加 200ms 余量，文字提示增加 1 秒余量，再加少量抖动。
4. **跨请求冷却。** 普通 `Resource has been exhausted` 无时间提示时，账号冷却从首次 5 秒改为 30 秒；未知 429 默认 60 秒，明确模型容量错误单独分类。明确配额耗尽仍按模型隔离，不把泛型 RESOURCE_EXHAUSTED 当作永久配额耗尽。
5. **刷新并发边界。** 账号已被选中但还在刷新 token 时，另一个请求可能记录新冷却；现在刷新结束后会重新检查账号、实际模型及持久冷却再返回账号。
6. **Penalty 能力错误。** 省略默认值 0；非零值正常转发。只有上游明确返回 penalty 不支持的 400 时，同账号最多重试一次并去掉 penalty，不改变其他参数。成功响应带 `X-Proxy-Parameter-Adjustments`，其他 400 不触发这种恢复。
7. **可诊断日志。** 最终失败日志保留分类、真实尝试次数、端点（如果可取得）和脱敏上游错误体，详情最多 8KiB，超限明确标记。控制台支持展开和复制错误，不再只能看被省略的短文字。

另外补回 demo 对 Claude SDK 独立身份块的精确转换；截图都是 OpenAI，不能用这一项解释截图中的失败。

## 52 秒的含义

无提示的 429 在五次尝试之间等待 5+10+15+20=50 秒，加上网络和抖动约为 52 秒。本地模拟复现了这一控制流，demo 也有该线性等待，所以没有把等待时间简单删掉来降低日志耗时。改善成功率仍取决于正确出站参数、上游恢复时间和账号状态。
