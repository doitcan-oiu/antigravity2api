# 反代修复与运行说明

更新：2026-09-07。针对根目录 Go 服务与 demo 的差异审计，已修改代理、调度、协议转换和生命周期代码。审计前的问题与复现记录保留在 [对照报告](proxy-parity-review.md)。

| 问题 | 当前实现 |

## 并发设计

当前适合**单节点、有明确并发上限的服务**，不是已经具备横向扩容能力的分布式平台。

- API 活跃请求默认最多 128 个；包含活跃请求在内的入口接纳量最多 256 个。队满立即返回 503，等待名额超过 5 秒也返回 503。
- 单账号默认最多 4 个在途上游请求。粘性会话不会绕过这个上限；没有空闲账号时可取消地等待释放。
- 请求取消传递到选号、token 刷新、上游读取和重试等待。SSE 每次写入设 30 秒截止时间，慢客户端不会无限占用名额。
- SQLite 使用 WAL、单写连接和 4 个只读连接。热路径选号不再逐请求 SELECT/UPDATE；使用时间合并更新，日志批量异步写入。
- 日志队列容量 2048，批次上限 128，约每 100ms 刷写。队满会丢日志并递增诊断计数，因此日志不是保证无损的审计队列。
- 导入、健康检查、刷新使用有界并发和可取消任务；退出时停止后台任务、等待请求，排空日志，再关闭数据库和空闲连接。
- 会话绑定最多 4096 条、冷却记录最多 8192 条；Responses 历史最多 256 条/32MiB，单条最多 2MiB，保留 30 分钟；签名缓存最多 4096 条/16MiB，单条最多 256KiB。
- 请求体上限 32MiB，单个 SSE 事件上限 32MiB，非流聚合上限 128MiB。上限是异常保护，不代表并发开启这些上限时内存一定足够。

应按机器内存、输入大小、流持续时间和账号数量设置 `MAX_CONCURRENT_REQUESTS`。图片和长上下文会显著增加每请求内存。提高 `MAX_CONCURRENT_PER_ACCOUNT` 不会增加上游额度，可能反而增加 429。服务本地并发控制不能消除上游真实限流。

Compose 已透传新增并发/超时变量，默认停机宽限为 40 秒。如果增加 `SHUTDOWN_TIMEOUT_SECONDS`，同时增加 Compose 的 `stop_grace_period`。

## 观察限流和运行状态

管理端新增 `GET /api/diagnostics`，使用 ADMIN_TOKEN：

```bash
curl -H "Authorization: Bearer $ADMIN_TOKEN" http://127.0.0.1:8080/api/diagnostics
```

返回各账号的进行中请求数和账号/模型冷却、活跃/排队请求、并发配置、`upstream_attempts`、`upstream_429`、入口拒绝数及数据库/日志队列指标。这些是单进程指标，重启归零；瞬时队列快照不提供事务一致性。

`upstream_429` 包含被重试恢复的 429，而控制台请求日志记录每个逻辑请求的最终结果。`upstream_attempts` 统计代理层调用，不包含 Cloud Code 客户端内部端点回退或 OAuth/配额查询次数。

账号列表、详情及概览已接入内存冷却状态。概览限流数包含存在模型冷却的账号；仅个别模型冷却不会把整个账号标记为不可用。

启用日志时，进程输出 `upstream attempt failed`，包含 request_id、原模型/实际模型、账号内部 ID、attempt、状态、分类和等待时长。流发出后发生错误时不能再改 HTTP 200，但会记录实际失败状态，而不会记为空成功。

## 保留的能力边界

- 单实例内存状态不跨进程共享：冷却、账号占用、签名和 Responses 历史在重启后清空。多副本共用账号会各自计算并发，不能据此保证全局上限；不要将同一 SQLite 文件放到网络文件系统供副本并发写入。
- 多节点部署还需要独立的共享存储、全局账号租约/限流及共享会话方案。此次没有引入未经验证的 Redis/PostgreSQL 集群，也没有修改现有数据格式进行这类迁移。
- 保留当前一个全局出站代理配置。demo 的逐账号代理绑定/代理客户端池不是本次已实现功能；即使配置值相同，实际出口是否一致仍需要运行环境确认。
- TLS 指纹仍采用 Go 现有 req/uTLS 配置，没有认定指纹差异就是 429 根因。
- Responses 不支持 background。previous_response_id 受上述缓存限制；失效返回 404，应由客户端发送完整历史。工具签名优先由客户端原样回传，缓存只做补充。
- Chat/Responses/原生 Gemini 请求只支持 n/candidateCount 为 1。Legacy 仅支持字符串 prompt；echo、suffix、logprobs 等未实现选项明确拒绝。未知扩展字段不保证等价支持。
- Images 支持生成和编辑、JSON/multipart、n=1、最多 8 张输入图；单文件 16MiB、请求 32MiB。图片须上传或使用内联 data URL；不下载远程图片，不支持 mask 和 Images streaming。url 输出为内联 data URL，不是持久化托管地址。
- 音频转录支持 WAV、MP3、M4A/MP4、OGG、FLAC、WebM 的上传，输出 JSON 或 text；不虚构分段时间戳。
- 同时传内置搜索和函数工具会返回明确错误；schema 采用适配而非完整 JSON Schema 执行器。未移植 demo 的所有提示词注入、上下文压缩及第三方服务功能。

## 验证

已通过 Go 全包测试、全包 race、go vet，以及 Go 可执行文件构建、前端 TypeScript 检查和生产构建。测试使用临时 SQLite、合成账号和本地 HTTP mock，覆盖：

- 10 账号 500 次选号的公平性：每号 50 次，修复前同秒情况下一个账号占 491 次。
- 120 条并发 HTTP 逻辑请求：10 个账号均被使用，每账号峰值不超过 4，无槽位泄漏。
- 限流分类、短等后同号成功、账号耗尽后保留 429、首帧错误、流内中断及取消。
- 管理/API 鉴权隔离、独立计数、Responses 多轮与完成缓存时序、工具/签名/usage、多模态及非法请求。
- token 刷新合并、关闭并发、数据库连接耗尽时取消、日志排空及写入队列行为。
- 真实本地 HTTP 传输中的 Content-Length、多值头、307 重放、端点回退及流读取取消。
- 编译后二进制使用临时数据目录启动：健康检查、嵌入前端、诊断接口、密钥隔离和 SIGTERM 正常退出。

没有用真实账号压测，没有宣称线上 429 已归零。上述并发用例验证程序行为，不代表上游吞吐量或生产容量。修改后仍应通过正常流量对照实际错误分类、映射模型和最终成功率。
